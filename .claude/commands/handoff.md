# 🤝 /handoff — تحديث الذاكرة المشتركة قبل الرفع

الهدف: أن يجد Claude على **الجهاز الآخر** (ويندوز ↔ ماك) صورة صادقة ومحدَّثة عن المشروع
بمجرّد `git pull`. لذلك يُحدَّث [`docs/الحالة_الحالية.md`](../../docs/الحالة_الحالية.md) بحقائق
**مفحوصة**، لا منقولة عن الذاكرة.

## الخطوات

### 1) افحص الحالة الفعلية (لا تخمّن)
شغّل هذه الفحوص واجمع نتائجها الحقيقية:

```bash
flutter analyze lib
flutter test
cd functions && npx eslint index.js && cd ..
git status --short
git log --oneline -3
```

### 2) حدّد ما يحتاج نشراً
قارن آخر تعديل على هذه الملفات بآخر عملية نشر:
- `functions/index.js` → `firebase deploy --only functions`
- `firestore.rules` → `firestore:rules`
- `storage.rules` → `storage`
- `firestore.indexes.json` → `firestore:indexes`

إن كان أيٌّ منها مُعدَّلاً ولم يُنشر، **اذكره صراحةً** في قسم «معلّقات معروفة».

### 3) أعد كتابة `docs/الحالة_الحالية.md`
حدّث هذه الأقسام تحديداً (وأبقِ البنية كما هي):

| القسم | ما يُحدَّث |
|---|---|
| الترويسة | التاريخ · **الجهاز** (💻 ويندوز / 🍎 ماك) · آخر عمل منجز |
| 3) أين وصلنا | ما أُنجز فعلاً هذه الجلسة + مؤشّرات الجودة **من الفحص الحقيقي** |
| 4) الخطوة التالية | ما اتُّفق عليه صراحةً مع المالك — لا اجتهاد |
| 5) معلّقات معروفة | ما ينتظر نشراً · ما لا يعمل · ما لم يُختبر |

### 4) لا تفعل
- ❌ لا تكتب «تمّ» لشيء لم يُفحص فعلاً.
- ❌ لا تحذف المعلّقات لمجرّد أنها قديمة — احذفها فقط عند حلّها.
- ❌ لا تلمس `craftsman_backup/` بأي شكل.
- ❌ لا ترفع أسراراً (`touba_release.jks` · `key.properties` · `local.properties`) ولا ملفات Firebase.

### 5) اختم بتذكير الرفع
اعرض على المالك أوامر الرفع الجاهزة، ولا تنفّذ `git push` إلا إن طلبه صراحةً:

```bash
git add -A
git commit -m "<وصف موجز للعمل>"
git push
```

## ملاحظة عن الجهاز الآخر
ذكّر المالك بأن تسلسل الاستئناف على الجهاز الآخر هو:
```bash
git pull
git submodule update --init --recursive
flutter pub get
```
