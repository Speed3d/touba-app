## السياق
بعد اكتمال الوجبة الرابعة (MVP ≈95%، نُشرت)، قدّم المالك وجبة خامسة فيها إصلاحات + ميزتان كبيرتان معماريتان: **مباريات التحدي + المحادثات**، و**نظام الاشتراكات**. النظامان الكبيران **مطبّقان ويعملان في «حرفي العراق»** (`craftsman_backup/`) — القرار: إعادة استخدام أنماطهما المُجرّبة.

## القرارات المحسومة (من نقاش المالك)
1. **الاشتراكات:** **الكابتن فقط** يدفع (اللاعبون مجاناً). يفتح الاشتراك: **طلب التحدي + إنشاء/المشاركة في بطولة**. **التفعيل يدوي من الأدمن** خارج التطبيق (واتساب/زين كاش/نقداً) عبر **أكواد تفعيل** (نمط حرفي). تجربة مجانية تُضبط مدتها من لوحة الأدمن.
2. **مباريات التحدي:** **ترتيب ودّي + محادثة، بلا إحصائيات** حالياً.
3. **تعارض الانضمام لعدة فرق:** **أول من يقبل يفوز** + إغلاق تلقائي لبقية الطلبات بعبارة «سجّل بفريق آخر» (بلا إشعار رفض للّاعب).
4. **الترتيب:** مراحل حسب الأولوية/الترابط.

## مراجع حرفي العراق المُعاد استخدامها (`craftsman_backup/`)
- **المحادثات:** `lib/data/services/chat_service.dart` + `chat_model`/`message_model`. مجموعة `chats` + `messages` (subcollection)، `participants[]` (استعلام arrayContains بلا فهرس مركّب)، عدّاد غير مقروء لكل طرف، `lastMessage/lastMessageTime`، رسالة نظام ترحيبية، فلترة كلمات محظورة (من `config/offensive_words`) + rate-limit + نظام مخالفات (strikes)، تنظيف محادثات منتهية (CF مجدول + fallback). **عام تماماً** (يصلح أي طرفين).
- **الاشتراك:** `lib/data/services/subscription_service.dart` + `activation_code_service` + `activation_code_model` + `admin_codes_tab.dart`. حقول على مستند المستخدم: `subscriptionStatus` (pending/free/active/expired) + `subscriptionExpiresAt`. أكواد لمدد (1/3/6 شهر) يولّدها الأدمن ويُدخلها الكابتن. فحص انتهاء ثلاثي الطبقات (CF مجدول يومي + fallback عند الفتح + تحقّق عند الطلب). كاش محلي للعمل دون نت (اختياري لنا).
- **علم الميزات (إظهار/إخفاء قسم):** نمط مستند `settings/system` بعلم منطقي + Switch في الأدمن + قراءة StreamBuilder (مثل `allowFreeRegistration`).

### المرحلة 7 — مباريات التحدي + المحادثة (بند 2) 🟢 ✅ منجزة (تحتاج نشر functions+rules)
**نُفِّذت (21 حزيران):** وحدة محادثة عامة (طرفان) + تحدّيات ودّية + دالتا إشعار + قواعد.
- **المحادثة (نمط حرفي مُعمَّم):** `chat_model` (participants[2]، أسماء/صور/unread كخرائط بمفتاح uid، lastMessage، expiresAt) + `chat_message_model` (نص/نظام). `chat_repository`: `createOrGetChat` (معرّف ثابت = uids مرتّبة، رسالة ترحيب)، `sendMessage` (تحقّق فراغ/طول/rate-limit 800ms/فلترة `config/offensive_words` + احتياط محلي)، `streamUserChats`/`streamMessages`/`streamUnreadCount`/`markAsRead`. شاشتان: `chats_list_screen` + `chat_screen` (فقاعات + بثّ حيّ).
- **التحدّيات:** `challenge_model` (+ `ChallengeApplicant`) + `challenge_repository` (إنشاء/مفتوحة/طلباتي/تقدّمت إليها/apply/cancel/matchWith). `challenges_screen` بتبويبين: «طلبات الفرق» (المفتوحة → «أوافق على التحدي») و«تحدياتي» (طلباتي + المتقدّمون → «قبول» يفتح محادثة + يقفل الطلب · ما تقدّمت إليه بحالاتها). إنشاء طلب عبر شيت (ملاحظة + موعد اختياري، المدينة من الفريق).
- **نقطة الدخول:** كرت «فريقي» للكابتن → زرّا «تحدّيات الفرق» و«محادثاتي». ونقر إشعار التحدي يفتح المحادثة/شاشة التحديات.
- **CF:** `onChallengeApplied` (إشعار صاحب الطلب) + `onChallengeMatched` (إشعار الفريق المختار) — عبر `_sendUserNotification`. **قواعد:** `chats`+`messages` (المشاركان فقط) + `challenges` (الإنشاء لصاحبه، التحديث: صاحبه يدير أو متقدّم يضيف نفسه). **لا فهارس مركّبة** (ترتيب محلي + حقل واحد).
- ⚠️ **القفل بالاشتراك مؤجّل للمرحلة 8** (خطّاف `_canChallenge` في `challenges_screen`). `analyze=0`·`eslint=0`·17 اختبار.
- **تحسينات بعد اختبار المالك (21 حزيران، نُشرت القواعد+الدوال):** (1) **طلب مفتوح واحد لكل كابتن** — `getMyOpenChallenge` يمنع نشر ثانٍ؛ حوار «لديك طلب مفتوح» (تعديل/إلغاء) + `updateChallenge` (تعديل الملاحظة/الموعد) + زر «تعديل» على الكرت. (2) **الأدمن يلغي الطلبات المتروكة** — `admin_challenges_screen` (يُبرز «متروك» ≥3 أيام بلا متقدّمين) + بطاقة في لوحة الأدمن + قاعدة التحديث تسمح للأدمن. (3) **الضغط على الكرت يفتح صفحة الفريق** — بطاقة الطلب وصفوف المتقدّمين قابلة للضغط → `TeamDetailsScreen` (يشاهد صاحب الطلب والمتقدّمين قبل القبول). (4) خطأ `PERMISSION_DENIED` عند القبول كان بسبب عدم نشر القواعد — حُلَّ بالنشر.

#### (المواصفات الأصلية للمرجع)
- **وحدة محادثة عامة** مُعاد بناؤها من نمط `chat_service` الحرفي: `chats` + `messages`، `participants[]`، streams حيّة، عدّاد غير مقروء، فلترة + rate-limit، رسالة ترحيب. تُستخدم لكابتن↔كابتن (التحدي) — وقابلة للتوسعة لكابتن↔لاعب لاحقاً.
- `challenges` collection: {requesterTeamId, requesterTeamName, city, note, status: open/matched/cancelled, applicants[], matchedTeamId, matchedTeamName, createdAt}. شاشة بتبويبين:
  - **طلبات الفرق:** كل الطلبات المفتوحة → فتح طلب → صفحة الفريق الخصم → زر «الموافقة على التحدي» (يُسجَّل في applicants) → إشعار لصاحب الطلب.
  - **تحدياتي:** طلباتي (مرسلة بكل حالاتها) + الطلبات التي قبلتُها. صاحب الطلب يختار من المتقدّمين → موافقة → البطاقة تُقفل («تم القبول») + محادثة تُفتح بين الكابتنين + إشعار للطرف الثاني. الكارت يعرض التاريخ والخصم.
- CF: إشعارات عند التقديم/القبول + (اختياري) فتح المحادثة من CF. قواعد `challenges` + `chats`/`messages`. **نشر functions + rules.**

### المرحلة 8 — الاشتراكات (الكابتن فقط، تفعيل أدمن بالأكواد) 🔴
- **UserModel (كابتن):** `subscriptionStatus` + `subscriptionExpiresAt`. عند تسجيل كابتن: تجربة مجانية = now + `freeTrialDays` (من `settings/subscription`).
- **أكواد التفعيل** (نمط حرفي): مجموعة `activation_codes` {code, durationDays, used, usedBy, createdAt, usedAt}. شاشة أدمن تولّد أكواد (1/3/6/12 شهر) + قائمة (مستخدم/غير مستخدم). الكابتن يُدخل الكود في التطبيق → CF `redeemActivationCode` يتحقّق (غير مستخدم) ويمدّد `subscriptionExpiresAt` (+المدة) ويضبط status=active ويعلّم الكود مستخدماً.
- **القفل:** helper `isSubscriptionActive(user) = expiresAt > now`. يُطبَّق على: زر طلب التحدي + إنشاء بطولة + المشاركة في بطولة (إضافة فريق غير مشترك كابتنه). رسالة واضحة عند القفل + إرشاد للتفعيل (واتساب الأدمن).
- **فحص الانتهاء:** الأبسط = مقارنة `expiresAt > now` لحظة القفل (لا حاجة لقلب الحالة). اختيارياً CF مجدول يومي يقلب expired (نمط حرفي).
- قواعد: `subscriptionStatus`/`subscriptionExpiresAt` يكتبها CF/أدمن فقط (لا الكابتن). `activation_codes`: إنشاء/قراءة أدمن؛ الاستهلاك عبر CF.
- **نشر functions + rules.**
