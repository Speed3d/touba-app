## ١) تثبيت الأدوات (مرة واحدة)

```bash
# Homebrew (إن لم يكن مثبّتاً)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Node.js (يجلب npm معه) — مطلوب لـ Firebase CLI والدوال
brew install node

# Firebase CLI
npm install -g firebase-tools

# تسجيل الدخول لحساب Google صاحب المشروع (يفتح المتصفح)
firebase login

# اعتماديات دوال السحابة (مرة واحدة + بعد أي تغيير على functions/package.json)
cd functions && npm install && cd ..

# (اختياري) أداة FlutterFire لإعادة توليد إعدادات Firebase
dart pub global activate flutterfire_cli
```

تحقّق من الإصدارات: `node -v` · `npm -v` · `firebase --version` · `flutter --version`

## ٢) أوامر Flutter اليومية

```bash
flutter pub get          # جلب الحزم
flutter clean            # حذف مخرجات البناء والكاش
flutter analyze lib      # فحص الكود (يجب أن يبقى نظيفاً)
flutter test             # تشغيل اختبارات الوحدة
flutter doctor           # فحص صحّة البيئة
flutter devices          # عرض الأجهزة/المحاكيات المتصلة
flutter pub upgrade      # ترقية الحزم ضمن قيود pubspec
```

### تشغيل التطبيق (Run)
```bash
flutter run                          # تشغيل على الجهاز المتصل (debug)
flutter run --release                # تشغيل بوضع الإصدار (أسرع)
flutter run -d <deviceId>            # تحديد جهاز (من flutter devices)
flutter run -d chrome                # تشغيل على الويب (متصفح Chrome)
```

### تركيبة سريعة: تنظيف + جلب + تشغيل
```bash
flutter clean && flutter pub get && flutter run
```

## ٣) بناء Android (APK / AAB)

```bash
# APK تجريبي (debug)
flutter build apk --debug

# APK إصدار (موقّع — للتوزيع المباشر/الاختبار)
flutter build apk --release

# APK مقسّم حسب المعمارية (أحجام أصغر — مفضّل للاختبار على الأجهزة)
flutter build apk --release --split-per-abi

# App Bundle (AAB) — الصيغة المطلوبة لرفع Google Play
flutter build appbundle --release

# تثبيت APK على جهاز متصل مباشرةً
flutter install
```

📂 مخرجات البناء:
- APK: `build/app/outputs/flutter-apk/app-release.apk`
- AAB: `build/app/outputs/bundle/release/app-release.aab`

⚠️ **توقيع الإصدار:** بناء `--release` يتطلّب وجود `android/key.properties` وملف الـ keystore (`touba_release.jks`, alias `touba`). هما محفوظان **خارج المستودع** — أعِدهما لمكانهما قبل بناء الإصدار، وإلا يفشل التوقيع أو يرجع لتوقيع debug.

## ٤) بناء iOS (IPA) — يتطلّب macOS + Xcode

```bash
# تثبيت اعتماديات iOS (بعد أي تغيير على الحزم)
cd ios && pod install && cd ..

# بناء iOS (بلا أرشفة)
flutter build ios --release

# بناء IPA — لرفع App Store / TestFlight (يتطلّب حساب Apple Developer + توقيع)
flutter build ipa --release

# فتح المشروع في Xcode (للأرشفة والرفع اليدوي والتوقيع)
open ios/Runner.xcworkspace
```

📂 مخرج IPA: `build/ios/ipa/*.ipa`
ℹ️ ملف `codemagic.yaml` مُعدّ لبناء iOS آلياً عبر CI (Codemagic).

## ٥) الويب (Build + Deploy)

```bash
# بناء نسخة الويب
flutter build web --release

# (مرة واحدة) إعداد استضافة Firebase — اختر مجلد build/web كـ public
firebase init hosting

# نشر الويب على Firebase Hosting
firebase deploy --only hosting
```

📂 مخرج الويب: `build/web/`
ℹ️ عند `firebase init hosting`: حدّد `build/web` كـ public directory، وأجب «نعم» لـ single-page app، و«لا» لإعادة الكتابة على `index.html`.

## ٦) Firebase — الدوال والقواعد والفهارس

```bash
# 🚀 النشر الأساسي بعد أي تعديل خلفية (الأكثر استخداماً)
firebase deploy --only functions,firestore:rules,firestore:indexes

# نشر كل شيء (دوال + قواعد + فهارس + تخزين + استضافة)
firebase deploy

# أجزاء مفردة
firebase deploy --only functions                 # كل الدوال
firebase deploy --only functions:rateReferee     # دالة واحدة فقط
firebase deploy --only firestore:rules           # قواعد Firestore
firebase deploy --only firestore:indexes         # فهارس Firestore
firebase deploy --only storage                   # قواعد Storage

# أدوات مساعدة
firebase functions:log          # سجلّات الدوال (الأخطاء/التتبّع)
firebase projects:list          # عرض المشاريع
firebase use touba-3ds          # تثبيت المشروع الحالي
```

⚠️ نشر الدوال يشغّل `eslint` تلقائياً (predeploy)؛ يجب أن يكون نظيفاً. ويتطلّب تفعيل **Blaze** (الفوترة) على المشروع.
