## 0. القرارات الحاكمة المُقرّة (A–D)

| # | القرار | الحسم |
|---|---|---|
| **A** | بنية شاشات البطولة | **تبقى الشاشتان منفصلتين** (`TournamentDetailsScreen` من «البطولات» + `TournamentMatchesScreen` من «المباريات»)، ويُكمَّل كلٌّ على حدة. |
| **B** | محرّك النتيجة الحيّة | تُحدَّث `homeScore/awayScore` بحرية أثناء `live` (تُعرض للمشاهد)؛ `resultConfirmed=true` **مرة واحدة فقط** عند التأكيد النهائي → المحرّك يطبّق الإحصائيات. تأكيد الشوط = حفظ للعرض بلا تشغيل المحرّك. |
| **C** | تقدّم الإقصائي/المجموعات | ترقية الفائزين **تلقائياً عبر CF عند التأكيد** + **تعديل يدوي** للطوارئ. عدد المتأهّلين والتزاوج **يحدَّدان عند الإنشاء** ويُعرضان في التفاصيل. تزاوج قياسي تلقائي (A1×B2…) + تخصيص لاحق. دعم **قوّة 2 وBye** لكل السيناريوهات. توليد إقصائي المجموعات تلقائي + زر يدوي. مباراة متعادلة في الإقصائي: حقل «كيف حُسمت» + اختيار المتأهّل. |
| **D** | نموذج الحكم | **حساب حكم عبر نفس التسجيل** (خيار دور ثالث) + **صفحة عامة**، مع إبقاء مسار «لاعب/كابتن يقدّم ليصير حكماً». حساب الحكم المباشر = حكم فقط (بلا فريق/بطاقة لاعب). التقييم: **المنظّم + الأدمن + كابتنا فريقَي المباراة فقط**، مرة واحدة لا تُعدَّل، والحكم لا يقيّم نفسه. |

## 3. WS5 — الحكّام: نموذج وتقييم (٣، ٩، ١٠)

**النماذج:** `role` يقبل `referee`؛ توسعة `refereeProfiles` بـ `city`/`bio`/`matchesCount`.

**القواعد:** `users.create` → `role in ['user','captain','referee']`؛ `referee_ratings` تُقفل للعميل (`create,update: if false`) فالتقييم عبر CF حصراً.

**الدوال:**
- جديدة `onUserCreated` (trigger على `users/{uid}`): إن `role=='referee'` → منح صفة `referee` (Custom Claim + `adminPermissions`) + إنشاء `refereeProfiles/{uid}`.
- جديدة `rateReferee` (callable): تحقّق أن المستدعي منظّم/أدمن/كابتن أحد فريقَي المباراة، و`raterId!=refereeId`، والمباراة منتهية، ولا تقييم سابق → يكتب التقييم → `onRefereeRatingWritten` تجمّع.

**الواجهة:** خيار «حكم» في [`register_screen.dart`](../lib/presentation/screens/auth/register_screen.dart)؛ **`RefereeProfileScreen`** جديدة (صفحة الحكم العامة)؛ بطاقة التقييم في [`match_detail_screen.dart`](../lib/presentation/screens/matches/match_detail_screen.dart) تستدعي `rateReferee` وتظهر للمؤهَّلين فقط؛ [`tournament_repository.applyAsReferee`](../lib/data/repositories/tournament_repository.dart) يمنع التقديم عند وجود `pending` أو `approved`.

## 4. WS3 — البطولات الإقصائية: حسم التعادل + الشجرة (٦، ٧)

**`TournamentModel` +:** `qualifiersPerGroup`(1|2|3) · `tieBreakMode`(`extratime_penalties`|`penalties`) · `groups`(Map) · `knockoutSeeding`(Map) · `stage`(`groups`|`knockout`|`finished`) · `bracketGenerated`(bool) · `standings[].group`.

**`MatchModel` +:** `stage`(`group`|`knockout`) · `groupName` · `bracketRound`(+تسمية مشتقّة) · `homeFeedFrom`/`awayFeedFrom`(matchId؟) · `decidedBy`(`none`|`extratime`|`penalties`) · `penaltyHome`/`penaltyAway` · `advancedTeamId`.

**`fixtures_service.dart`:** إعادة كتابة `knockout` برؤوس مرتبطة (feed) + Bye لأقوى المتصدّرين؛ `groups` يخزّن `groupName`؛ جديدة `seedKnockoutFromGroups` (تزاوج قياسي + Bye).

**الدوال:**
- `onMatchResultConfirmed`: تخطّي فرق TBD/Bye؛ ترتيب واعٍ بالمجموعات؛ ترقية الفائز (`advancedTeamId` أو الأعلى) لخانة المباراة التالية؛ تعديل يدوي يعيد الترقية بلا تكرار.
- جديدة `generateKnockoutFromGroups` (تلقائي عند اكتمال المجموعات + callable يدوي، idempotent عبر `bracketGenerated`).
- `finalizeTournamentIfDone`: تُنهي عند اكتمال المرحلة الإقصائية؛ البطل = فائز النهائي.

**الواجهة:** خيارات الإنشاء (حسم التعادل + المتأهّلون + التزاوج) في [`create_tournament_screen.dart`](../lib/presentation/screens/tournaments/create_tournament_screen.dart)؛ **`BracketView`** + شاشة شجرة تتقدّم تلقائياً.

## 5. WS2 — المحرّك الحيّ (٤، ٥، تأكيد الشوط في ٢)

**`MatchModel` +:** `periodScores`(List‹{period,home,away}›).

**`match_repository.dart`:** `updateLiveScore` · `addLiveEvent`/`removeLiveEvent` · `confirmHalf` (عرض فقط) · تعديل `setResult` ليقبل حقول الحسم ويؤكّد مرة واحدة.

**`match_detail_screen.dart`:** نص متناسق (live/upcoming/finished) + سكور حيّ في الرأس؛ لوحة تحكّم المنظّم/الأدمن داخل الشاشة (بدأ/إدخال لحظي/حدث/انتهاء شوط/تأكيد نهائي + حسم تعادل الإقصائي)؛ المشاهد يرى السكور والمؤقّت فقط. نقل التحكّم من كارت [`tournament_details_screen.dart`](../lib/presentation/screens/tournaments/tournament_details_screen.dart).

## 6. WS4 — شاشات البطولة (٢، ١١، ١) — الشاشتان منفصلتان

- **«البطولات» → `TournamentDetailsScreen`:** 3 تبويبات (تفاصيل / شروط وقوانين / **الفرق المشاركة**). تبويب الفرق: كل الفرق + حالة التشكيلة (لم يُرسل/أُرسل/تحقّق/مرفوض)؛ فريق لم يُرسل → نافذة تنبيه الكابتن (CF، التنفيذ يدوي)؛ لاعب في التشكيلة → فتح `PlayerDetailScreen` (`onSlotTap`).
- **أزرار المراجعة (١):** [`tournament_lineups_review_screen.dart`](../lib/presentation/screens/tournaments/tournament_lineups_review_screen.dart) — بعد القرار تختفي الأزرار وتُستبدل بشارة + «تغيير القرار».
- **«المباريات»:** [`MatchesScreen`](../lib/presentation/screens/matches/matches_screen.dart) يفصل جارية/منتهية بعناوين؛ [`TournamentMatchesScreen`](../lib/presentation/screens/matches/tournament_matches_screen.dart) يضيف **كارت «جدول الترتيب»** → جدول (دوري) / ترتيب المجموعات / `BracketView` (إقصائي).

## 7. النشر والاختبار

```bash
firebase deploy --only functions,firestore:rules,firestore:indexes
```

**نقاط اختبار حرجة:** (1) لا ازدواج إحصائيات رغم تحديث السكور الحيّ. (2) ترقية الشجرة صحيحة + Bye لـ3/5/6/7 فرق + تعديل يدوي بلا تكرار. (3) توليد إقصائي المجموعات idempotent والتزاوج صحيح. (4) صلاحية التقييم محصورة ولا تقييم للنفس/مكرّر. (5) `onUserCreated` يمنح صفة الحكم ويظهر في `getReferees`.
